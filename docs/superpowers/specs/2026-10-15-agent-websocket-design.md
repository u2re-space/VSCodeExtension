# WebSocket-клиент Universal-AI

Дата: 2026-10-15. Расширение `U2RE-toolset` (`vext.*`) подключается к уже запущенному `ai serve` и умеет само поднять этот процесс. Дополнение кода и боковая панель используют один порт и один токен, два разных сокета.

## Решения

- По умолчанию расширение только клиент. Запуск `ai serve` включается настройкой.
- Адрес берётся из `serve.json`, если `pid` жив. Ненулевой порт в настройках подменяет порт. Непустой токен в настройках подменяет токен файла, когда процесс поднял не расширение.
- `ai serve` на одном порту отдаёт шину команд и дополнение: `ws://127.0.0.1:<порт>` и `ws://127.0.0.1:<порт>/v1/complete`.
- Панель умеет `run`, `ask`, `chat` и `image`. Кнопки **Run** и **Ask** основные, **Chat** и **Image** в меню «Ещё».
- Tab показывает серый призрак вставки через `InlineCompletionItemProvider`. Принятие — штатный Tab редактора.
- GPTunnel (`vext.gptView`) не меняется.

`OPENAI_BASE_URL` и `OPENAI_API_KEY` читает процесс агента. Расширение передаёт их в окружение только своему дочернему `ai serve`, и только если значение в настройке непустое.

## Адрес

Каталог агента: `AI_AGENT_HOME`, иначе `path.join(os.homedir(), '.ai-agent')`. Файл: `serve.json`.

Живая запись содержит числовой `pid`, строку `url` вида `ws://127.0.0.1:<порт>` и строку `token`. `pid` жив, если `process.kill(pid, 0)` не бросает исключение. Мёртвый `pid`, битый JSON и отсутствие файла означают «сервера нет».

Настройки, которые участвуют в адресе:

- `vext.agent.port`, число, по умолчанию `0`. `0` не подменяет порт.
- `vext.agent.token`, строка, по умолчанию `""`. Пустая строка не подменяет токен.

Итог для уже запущенного сервера:

1. Есть живой `serve.json`: база — его `url` и `token`. Ненулевой порт заменяет порт в URL. Непустой токен заменяет токен, кроме случая, когда `ownPid` совпадает с `pid` файла: тогда токен всегда из файла.
2. Живого файла нет, порт и токен в настройках заданы: `ws://127.0.0.1:<порт>` и этот токен.
3. Иначе адреса нет.

`completeWs` всегда `${url}/v1/complete?token=${encodeURIComponent(token)}`. Заголовок `Authorization` не ставится: глобальный `WebSocket` его не принимает, сервер читает `?token=`.

## Запуск процесса

`vext.agent.launch` по умолчанию `false`. `vext.agent.command` по умолчанию `ai`.

При активации, если запуск включён и живого сервера нет, расширение один раз порождает процесс:

- аргументы: `serve`, и `--port <n>`, когда порт в настройках ненулевой;
- `shell: true` только на Windows, чтобы находился `ai.cmd`;
- `windowsHide: true`;
- в окружение копируется `process.env`, затем непустые `vext.agent.openaiBaseUrl` и `vext.agent.openaiApiKey` записываются в `OPENAI_BASE_URL` и `OPENAI_API_KEY`.

Дальше 10 секунд опрашивается `serve.json`, пока `pid` не совпадёт с живым процессом. Токен этого запуска всегда берётся из нового файла, даже если в настройках токен заполнен: `ai serve` генерирует токен сам и не принимает его флагом. Команда **Остановить** завершает этот `pid` и дочерний процесс. Чужой сервер она не трогает. Повторный старт при живом `pid` не порождает второй процесс.

Команды:

- `vext.agent.start` — запустить, даже если `vext.agent.launch` выключен;
- `vext.agent.stop` — остановить только свой процесс;
- `vext.agent.reconnect` — закрыть оба сокета и собрать адрес заново.

Смена любой настройки `vext.agent.*` заново собирает адрес и переоткрывает сокеты. Если `vext.agent.launch` включён и живого сервера нет, выполняется тот же старт, что при активации. Команда переподключения процесс не порождает.

## Шина

Одно соединение на `url`. Первый кадр: `{ "type": "hello", "role": "client", "token": "<token>" }`. Ответ `ready` переводит панель в состояние готово. Кадры — JSON-тексты.

Одновременно у панели один свой запуск. `runId` запоминается из `run.started`, если владелец — этот сокет (запуск пришёл после нашего `start`).

| Действие | Кадр |
|---|---|
| Run, Ask, Image | `{ type: "start", command, prompt, cwd, approve }`. Непустой `prompt`. Перед этим, если свой запуск ещё идёт, `{ type: "cancel", runId }` |
| Первое сообщение Chat | тот же `start` с `command: "chat"` |
| Следующие сообщения, пока Chat не завершён | `{ type: "input", runId, text }` |
| Yes / No / Always / Abort | `{ type: "approve", requestId, decision }` |
| Ответ на вопрос | `{ type: "answer", requestId, text }` |

`cwd` — `fsPath` первой папки workspace. Без папки `start` не отправляется, панель пишет «нет папки workspace». `approve` берётся из `vext.agent.approve` (`ask`, `read`, `write`, `all`), по умолчанию `ask`. Пустой промпт не отправляется. Пока своего `run.started` ещё нет, новая отправка не уходит на сервер: статус «запуск…».

Обрыв сокета: состояние «нет связи», пауза 2 с, затем 4, 8, 16 и далее 30 с. Успешный `ready` сбрасывает паузу. Кадр `error` с кодом `unauthorized` или закрытие `1008` останавливает повторы до переподключения или смены настроек.

## Панель

Контейнер activity bar `agentView`, заголовок `Universal AI`, иконка `assets/openai.svg`. View `vext.agentView`, имя `Agent`. Скрипты и `icons/webview.css` — локальные ресурсы webview, CSP как у менеджера: `default-src 'none'`, стили и скрипты только с nonce и `cspSource`.

Состояние сверху: адрес или причина, кнопки «Переподключить» и, если процесс наш, «Остановить». Ниже поле промпта, кнопки Run и Ask, меню «Ещё» с Chat и Image, лента.

Сообщения webview → хост: `ready`, `start`, `cancel`, `approve`, `answer`, `reconnect`, `stop`.

Хост → webview:

- `status`: `disconnected`, `connecting`, `ready`, `unauthorized`, `error`, плюс короткий текст;
- `run`: `runId`, команда, `started` или `ended`, код выхода;
- `text`: кусок `text.delta`;
- `log`: строка ленты;
- `approval`: `requestId`, имя, категория, превью;
- `question`: `requestId` и текст вопроса.

В ленту попадают `tool.exec.start`, `tool.exec.done`, `warning`, `error`, `image.saved` (путь), `response.done` (краткая строка usage, если она есть) и `run.ended`. `reasoning.delta` и `image.progress` меняют только строку состояния («думает…», «генерирует изображение…») и в ленту не пишутся. Картинка в панели не рисуется.

Пока Chat идёт, отправка из поля — это `input`, включая строки `/exit` и другие слэш-команды. Run, Ask и Image всегда начинают новый `start`.

Сокет шины открывается, когда view становится видимой, и при явном старте или переподключении.

## Tab

`languages.registerInlineCompletionItemProvider` для схем `file` и `untitled`. Провайдер зарегистрирован всегда. При `vext.agent.completion.enabled === false` (по умолчанию `true`) он сразу возвращает пустой список.

После последней просьбы редактора ждётся `vext.agent.completion.debounceMs` (по умолчанию `350`). Отменённый `CancellationToken` прерывает ожидание. Затем уходит один кадр:

```json
{ "type": "complete", "id": "<id>", "language": "<languageId>", "content": "<текст>", "cursor": { "line": 0, "character": 0 } }
```

`path` добавляется только для схемы `file`. `id` монотонный.

Размер считается как `Buffer.byteLength(text, 'utf8')`:

- документ не больше 262144 байт — весь текст и курсор редактора;
- иначе строки от `line - 200` до `line + 50` включительно, курсор пересчитан внутри этого среза;
- если JSON больше 900000 байт, радиус окна делится пополам (200/50, затем 100/25, 50/12, 25/6, 12/3, 6/1, затем только строка курсора);
- строка курсора сама больше 900000 байт — запрос не отправляется.

Ответ `completion` с тем же `id` и непустым `text` становится одним `InlineCompletionItem` с `insertText`. Диапазон не задаётся: вставка в курсор. Пустой текст и чужой `id` ничего не показывают. Сокет дополнения отдельный от шины и открывается по первому запросу. Ошибка пишется в строку состояния панели и в элемент статус-бара `U2RE Agent` на несколько секунд, без модального окна.

## Ошибки

| Ситуация | Поведение |
|---|---|
| Нет адреса | Оба клиента молчат, панель: «агент не запущен» |
| Порт занят при старте или файл не появился за 10 с | Панель и одно уведомление с текстом ошибки, процесс наш завершается |
| Неверный токен | Статус `unauthorized`, без перебора |
| Обрыв | Повтор с паузой до 30 с |
| Ошибка дополнения | Пустой список подсказок и короткая строка статуса |

## Проверки

`test/agent.test.js` вызывает чистые функции, без окна редактора:

Функция адреса принимает запись файла, настройки и `ownPid`. `ownPid` совпадает с `pid` файла, когда процесс запустило расширение.

- живой `serve.json` даёт его URL и токен;
- ненулевой порт меняет только порт;
- непустой токен меняет только токен, когда `ownPid` не совпадает с `pid` файла;
- мёртвый `pid` и отсутствие файла дают «сервера нет»; при совпавшем `ownPid` токен берётся из файла, даже если настройка токена заполнена;
- документ больше 262144 байт режется в окно, курсор смещается, огромная строка курсора не уходит в кадр;
- Run, Ask и Image строят `start` и перед этим `cancel`, если запуск ещё идёт;
- второе сообщение Chat строит `input`;
- кнопки подтверждения строят `approve` с `yes`, `no`, `always`, `abort`;
- `text.delta` становится `text`, `tool.exec.done` становится `log`, `reasoning.delta` в ленту не попадает.
